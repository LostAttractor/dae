# 日志

默认 `global.log_level: info` 关注服务是否正常工作。排查某条连接时使用 `debug`，需要逐包或处理步骤时使用 `trace`。`dae status` 的完整状态表不受此分类影响。

| 级别 | 记录内容 |
|---|---|
| `error` | 功能失败，例如路由状态写入失败、插件 worker 退出、服务意外停止 |
| `warn` | 需要关注的退化，例如组无可用节点、认证阻断恢复、使用缓存订阅、重载被拒绝 |
| `info` | 启动/重载完成、用户配置操作、节点选择、可用性变化和恢复 |
| `debug` | 单连接或请求失败、选路、重试、准备阶段和详细状态表 |
| `trace` | 包、帧、缓存、处理步骤、成功的周期探测、拥塞采样、eBPF 验证器详情 |

正常 EOF、调用方取消和主动关闭不告警。连接错误继续传播给状态管理者，由其记录可用性变化；不要在每层重复告警。持续重试只在进入故障时告警，恢复时提示；保留已有 UDP 队列拥塞日志的时间限制。

消息说明发生了什么和影响，节点、组、网络、来源、目标及错误放在结构化字段中。不要输出分享链接、认证数据、完整配置行或未经脱敏的资源 URL。错误保留原因，普通日志不展开堆栈。昂贵的包解析或字段构造需先检查日志级别。

文件等非 TTY 输出会引用、转义字段，避免多行错误拆成多条记录。TTY 保留彩色显示。守护进程统一遵守 `log_level`，默认写 stderr；配置 `--logfile` 后写入该文件。最终失败原因只记录一次。

Surge 自动请求追踪使用 `trace`；脚本显式 `console.log/info` 保持 `info`，其余 console 方法使用对应级别。命令结果、trace 导出和显式开启的第三方诊断是独立输出，不能当成后台日志统一丢弃。
