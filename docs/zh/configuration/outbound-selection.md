# 自动节点选择

`min`、`min_avg10`、`min_moving_avg`、`random` 和 `failover` 都先过滤不可用节点，再按**正常优先于故障降级 → priority 从高到低**选择。全部可用节点都已降级时，允许从降级节点中兜底。

## 延迟与故障降级

`min` 使用最近成功延迟，`min_avg10` 使用最近十次成功延迟的平均值，`min_moving_avg` 使用成功样本的移动平均（可配置 `min_moving_avg(alpha: 0.18)`）。失败不写入延迟统计；没有成功样本时延迟未知。

同一降级层级和优先级内，延迟策略比较 `实测统计值 + add_latency`。条件 `priority` 使用未加偏移的实测值。负 `add_latency` 不能覆盖降级或优先级；`check_tolerance` 只用于同层延迟比较。

确认故障后节点降级。首次测试成功即可降级兜底，并开始 `failure_recovery` 窗口，按 `min(check_interval, 5s)` 重复测试；到期验证成功才解除降级。确认故障或停止观察会重启未完成的窗口。共享路径复用测试，各组独立使用观察时长。目标错误、取消、排队超时和休眠不直接算路径故障，也不能替代成功验证。

`check_interval` 是健康节点持续监测的间隔，默认 `3m`；恢复观察临时缩短验证间隔，默认约每 `5s` 一次，并在 `30s` 窗口到期时验证。窗口从首次恢复成功开始计算；时间到期本身不能解除降级。

## `policy: failover`

```text
group {
    proxy {
        filter: subtag(primary) [priority: 10]
        filter: subtag(backup) [priority: 1]
        policy: failover

        failure_recovery: 30s
        probe_timeout: 3s
        selection_timeout: 15s
        upgrade_interval: 3m
        upgrade_interval_max: 1h
    }
}
```

示例列出默认值，这些参数要求显式自动策略，时长必须为正数。

`failover` 不为健康的当前节点和同级备用维持周期测速。手动测试、业务故障确认、共享组监测、恢复验证等产生真实结果后，仍按降级层级、优先级和最近成功延迟加 `add_latency` 重选，并遵守 `check_tolerance`；同层更优节点可以接替当前节点。已恢复可用的同层候选也会完成必要的恢复观察，观察结束后停止持续检查。静默故障在后续使用时发现。

当前节点的真实测试更新评分时，历史评分更优且未确认故障的休眠备用也参与一次限时验证；不能因物理资源已释放而遗漏同层候选。候选验证后不再更优时继续考虑其他候选，不会因此开启备用节点的周期测速。

启动及故障切换逐层测试，同层并发。固定优先级和偏移相同的候选可首个成功即接替；不同偏移或条件优先级只限时等待仍可能胜出的候选。条件优先级按可能最高值安排检查，按实测值选择。

`probe_timeout` 包含排队、建连和验证，`selection_timeout` 限制整轮。相同路径/网络的并发检查合并；触发重选的成功结果（包括恢复窗口末次测试）直接用于切换。结果绑定路径、网络能力和 Session 世代，新故障使其失效。

证明按目标网络分别保存；某个网络的成功不能刷新另一个网络的证明，历史能力支持也不能代替本次验证。故障使证明失效后，原选中节点也必须取得对应网络的新证明才能恢复使用。共享检查因较早调用者的短预算结束时，较长预算的调用者可在自身剩余时间内重新验证，等待期间继续持有传输资源；重试不会重置调用者的截止时间。

每个接替候选必须先通过对应目标网络的连通性验证。历史延迟和历史健康状态可用于排序；没有本轮可复用的成功证明时，候选必须重新验证，失败或超时则继续选其他候选。由本次成功测试直接触发的切换复用该证明，提交前再次检查有效性；会话建连成功不能代替连通性验证。当前节点仍可用时，候选验证在后台进行；当前不可用时，请求在总选择预算内等待已验证的接替者。

可能更优的候选按 `upgrade_interval` 接受升级检查，未升级时指数退避，带抖动且不超过 `upgrade_interval_max`。高优先级节点解除降级后回切。已有持续监测或恢复观察的路径复用对应网络的结果；接替或建立独立热备时，缺少有效证明的其他网络仍须单独验证。全组不可用时由组级退避恢复。

分层发现跨限时轮次保留已尝试记录，后续轮次先继续尚未尝试的候选，遍历完成后才重新开始；高层持续超时不会让低层兜底永远得不到验证。新的成功证明可让候选重新参与选择；业务请求仍共用原来的总等待预算。

## 持续测速与切换

持续测速策略只有在当前层级另有可用备援时，才让低优先级候选休眠。当前层级只有一个可用节点，或同级备援故障时，下层候选保持监测；同级备援恢复后再休眠。备援按目标网络分别判断，共享同一物理路径的别名不算独立备援。可能进入当前或更高层级的休眠候选通过升级检查发现。

当前节点可用时，后台验证候选，业务继续使用当前节点。启动或故障时才等待选举，单次请求总等待不超过 `selection_timeout`，重启选举或改试另一 IP 地址族不重置预算。替代选举保留已有内核路由状态，失败后才应用无连接回退和 `skip_while_noalive`。其他 direct 流量仍按原条件在内核直通。

## 调度职责

- **组调度器**：按目标网络维护选举与探测需求；提交前重新检查成功结果的有效性和当前排名，最优结果失效时仍可使用已验证的次优结果。
- **共享路径 worker**：串行执行单次验证、持续监测和恢复观察，合并同路径/网络的并发请求。各组共享探测结果，独立计算延迟统计、优先级和恢复时长。
- **传输生命周期**：汇总监测、选中、连接和证明持有需求。成功证明持有资源至交接完成；新故障或 Session 世代变化使旧证明失效。

## 休眠和状态

共享路径汇总各组及业务需求；没有监测、选中、探测或保留调用者/连接时释放物理会话，按需重建。休眠保留测量和降级记录；停止 dae 测速不等于关闭仍在使用的协议会话心跳。

仍有可接收会话但缺少池容量时，即使路径健康检查失败，也可补建缺失会话；成功补建后及时重新验证，不能用建连成功代替健康证明。补建使可用容量增加时继续补齐，失败或没有可见容量进展时退避；建连返回成功但新会话立即丢失也不能清除退避。选中或保留调用者的路径可在暂停周期测速时修复容量。

`status` 的 Last/Avg10/EMA 是成功延迟。故障期间显示 `[degraded]`，首次恢复成功后显示 `[recover 5s/30s verified]`。分子是成功探测已验证的恢复时长，不是实时计时：首次成功为 `0s`，只有后续成功探测才推进，等待或探测超时时可以停在 `0s`；`30s` 是解除降级所需的观察窗口，不是故障确认超时。

`STATE` 同时显示健康状态和 worker 当前动作，包括 `healthy (verifying connectivity)`、`healthy (recheck in 5.0s)` 和 `confirming (queued for check slot)`。恢复观察期间的 recheck 倒计时来自实际调度时间；探测失败后显示 `fail`。只有物理会话实际释放时才显示一次 `dormant`，历史延迟附带样本年龄。

API `selection.tracking` 只表示本组角色：`selected`、`monitoring` 或 `standby`。`standby` 不代表物理休眠或停止恢复：其他组可以共享监测结果，尚无监测的高优先级候选仍由升级调度发现。`recovery` 提供共享 worker 的动作及重试时间，节点的 `dormant` 单独表示物理休眠。`selection` 还提供 `recovery_elapsed`、`failure_recovery`、有效优先级、评分和 `measured_at`。

Prometheus 的 `dae_check_latency_seconds` 提供实测 `last`、`moving`；`dae_selection_score_seconds` 单独提供含偏移的选择评分，允许负数。
