# 自动节点选择

`min`、`min_avg10`、`min_moving_avg`、`random` 和 `failover` 都先过滤不可用节点，再按**正常优先于故障降级 → priority 从高到低**选择。全部可用节点都已降级时，允许从降级节点中兜底。

## 延迟与故障降级

`min` 使用最近成功延迟，`min_avg10` 使用最近十次成功延迟的平均值，`min_moving_avg` 使用成功样本的移动平均（可配置 `min_moving_avg(alpha: 0.18)`）。同一路径的已支持网络模式（`tcp4/tcp6/udp4/udp6`）共用代表探针的成功样本；各组按自己的统计参数计算。失败不写入延迟统计；没有成功样本时延迟未知。

同一降级层级和优先级内，延迟策略比较 `实测统计值 + add_latency`。条件 `priority` 使用未加偏移的实测值。负 `add_latency` 不能覆盖降级或优先级；`check_tolerance` 只用于同层延迟比较。

上游错误会触发故障确认，并发上报合并为对路径的一次探测。代理的 TCP 连接在调用方首次发出数据后，如果上游在探测超时（8 s）内一个字节也没有返回，同样触发确认：路径被黑洞时，调用方会先放弃，relay 本身不会产生错误。基于普通 TCP 的节点载体在数据 30 s 未被确认后关闭，这个时间长于一次失败的健康检查，连接池因此会替换被黑洞的连接；MPTCP 载体只能依赖 keepalive。

确认路径故障后，所有已支持模式共同降级；共享会话或认证故障同样影响整个路径。首次测试成功即可降级兜底，并开始 `failure_recovery` 窗口，按 `min(check_interval, 5s)` 重复测试；到期验证成功才解除降级。确认故障或停止观察会重启未完成的窗口。共享路径复用测试，各组独立使用观察时长。目标错误、取消、排队超时和休眠不直接算路径故障，也不能替代成功验证。

代表检查确认失败后，全部网络模式进入未知状态并重新发现，包括此前标为不支持的模式。选择器立即切换到存活的替代路径，不等待故障节点完成这一轮探测。成功模式可以成为新代表；尚未重新确认的模式不接收流量。更换代表模式不会跳过 `failure_recovery`。

故障路径按自身的调度恢复：每次尝试等待目前停机时长的四分之一，至少 1 s，至多 `check_interval_max`，并带抖动。这样恢复会在停机时长约 25% 的时间内被发现，而一个长期失效的路径在等待时间四小时后达到默认 `1h` 上限之前，只需约 40 次尝试，之后每小时一次。Session 的变化，包括路径自身的重连尝试，都不会缩短等待。自动策略的组始终监测自己的故障候选，选举和升级检查跳过它们，路径恢复后通知共享它的所有组。selector 组只监测选中或跟踪的成员。某个模式确认后，其余未知模式按能力发现的退避调度：从 1 s 开始，每次乘 4，至多 `check_interval_max`。

`check_interval` 是健康节点持续监测的间隔，默认 `3m`；恢复观察临时缩短验证间隔，默认约每 `5s` 一次，并在 `30s` 窗口到期时验证。窗口从首次恢复成功开始计算；时间到期本身不能解除降级。

## 存活与切换

节点在当前 Session 中最近一次代表探测成功，且没有待确认的故障时，处于存活状态。存活本身就是节点有效的证明：当前节点确认故障后，组立即切换到最优的存活节点，不为它重新探测；存活且排名更优的节点也直接接替当前节点。休眠、重连和确认中的节点都不存活。确认中的当前节点继续服务，确认故障后才切换。

当前节点故障后接替的节点，以及按延迟切换到的不受监测的节点，会接受一次验证。验证与存活一样只确认路径有效，使用代表探针，不逐个网络模式测试；它需要一个晚于切换依据的代表结果：节点正在进行的代表探测即可满足，空闲时立即探测一次，暂停周期测速时也会执行，同一节点的重复请求合并为一次。验证失败按普通健康失败处理，组随即切换到下一个存活节点。首次选择、新节点正是刚完成探测的节点，或者在持续监测的节点之间按延迟切换时，不做额外验证，监测本身持续刷新这些节点。

只有没有存活节点时才进行选举，例如启动期、全组故障，以及 `failover` 的备用均已休眠。选举进行中出现的存活节点（包括选举中第一个测试成功的节点）立即接替，选举继续；此后只有不计 `check_tolerance` 也更优的候选才再次切换，剩余层级都不可能更优时选举提前结束。

## `policy: failover`

```text
group {
    proxy {
        filter: subtag(primary) [priority: 10]
        filter: subtag(backup) [priority: 1]
        policy: failover

        failure_recovery: 30s
        probe_timeout: 3s
        selection_timeout: 15s
        upgrade_interval: 3m
        upgrade_interval_max: 1h
    }
}
```

示例列出默认值，这些参数要求显式自动策略，时长必须为正数。

`failover` 不为健康的当前节点和同级备用维持周期测速。手动测试、业务故障确认、共享组监测、恢复验证等产生真实结果后，仍按降级层级、优先级和最近成功延迟加 `add_latency` 重选，并遵守 `check_tolerance`；同层更优节点可以接替当前节点。已恢复可用的同层候选也会完成必要的恢复观察，观察结束后停止持续检查。静默故障在后续使用时发现。

当前节点的真实测试更新评分时，历史评分更优且未确认故障的休眠备用也参与一次限时测试；不能因物理资源已释放而遗漏同层候选。候选测试后不再更优时继续考虑其他候选，不会因此开启备用节点的周期测速。

备用不受监测，物理会话释放后即不再存活。当前节点确认故障时，仍存活的节点（例如由其他组监测或处于恢复观察）立即接替并接受一次验证；没有存活节点时才选举，请求等待选举结果。

选举逐层测试，同层并发，首个测试成功的候选立即接替。不同偏移或条件优先级的候选仍可能胜出时，选举限时等待其结果，胜出则再次切换。条件优先级按可能最高值安排检查，按实测值选择。已存活的候选不再探测，测试成功的候选即为存活节点。

`probe_timeout` 限制选举或升级检查对单个候选的一次测试，包含排队、建连和验证；`selection_timeout` 限制整轮选举。同一路径已支持模式的并发检查合并为一次代表探测。共享检查因较早调用者的短预算结束时，较长预算的调用者可在自身剩余时间内重新测试，重试不会重置调用者的截止时间；测试成功后传输保持唤醒，直到组提交或放弃该结果。

每个接替候选必须已确认支持目标网络。未知能力先单独发现，不能仅凭其他模式成功就认定支持；会话建连成功也不能代替连通性测试。历史延迟和历史健康状态可用于排序，测试失败或超时则继续选其他候选。

可能更优的候选按 `upgrade_interval` 接受升级检查，未升级时指数退避，带抖动且不超过 `upgrade_interval_max`。接替使服务层级下降（由更低层级或已降级的节点接替）时，更高层级中不受监测的候选立即接受一次升级检查；受监测的候选（包括按自身调度恢复的故障候选）恢复后会自行存活。高优先级节点解除降级后回切。持续监测或恢复观察中的路径由自身探测保持存活，不需要额外检查。全组不可用时，组级退避轮次只测试未在恢复中的候选；所有候选都在恢复中时，请求直接降级，不等待空的选举。

分层发现跨限时轮次保留已尝试记录，后续轮次先继续尚未尝试的候选，遍历完成后才重新开始；高层持续超时不会让低层兜底永远得不到测试。业务请求在选举轮次之间共用原来的总等待预算。

## 持续测速与切换

持续测速策略只有在当前层级另有存活备援时，才让低优先级候选休眠。当前层级只有一个可用节点，或同级备援故障时，下层候选保持监测，作为热备；同级备援恢复后再休眠。备援按目标网络分别判断，共享同一物理路径的别名不算独立备援。可能进入当前或更高层级的休眠候选通过升级检查发现。

当前节点可用时，休眠或尚未测试的更优候选在后台测试，业务继续使用当前节点。没有存活节点时才等待选举：单次请求的等待不超过 `selection_timeout`，也不超过请求自身的截止时间；重启选举或改试另一 IP 地址族不重置预算。选举期间保留已有内核路由状态；组尚未选出节点且此前没有选举失败时（例如启动期），内核把该组流量交给用户态等待选举，不提前降级。选举失败后组发布不可用，等待中和后续的请求按 `no_connectivity_behavior` 降级，并应用 `skip_while_noalive`；退避期间请求不再等待；组重新有可用节点后清除退避，此后的故障立即选举。请求自身已经结束时直接失败，不降级。其他 direct 流量仍按原条件在内核直通。

## 调度职责

- **组调度器**：按目标网络维护选择、选举与探测需求。节点检查结果通知组时同步决策，存活节点立即接替并按需请求验证。当前节点可用时，运行中的选举或候选测试负责该网络的决策；没有可用节点时，存活节点即使在选举中也立即接替。选举提交前重新检查候选仍存活及当前排名，最优结果失效时仍可使用测试成功的次优结果。
- **共享路径 worker**：调度单次测试、切换后验证、持续监测和恢复观察，合并同一路径已支持模式的并发请求。建连和代表探测属于整条路径，路径存活之前单次测试逐个执行并优先代表测试；之后不同网络模式的单次测试并发执行，互不排队，同一模式的测试以及其他操作依次执行。各组共享探测结果，独立计算延迟统计、优先级和恢复时长。
- **传输生命周期**：汇总监测、选中、连接和检查持有需求。成功检查持有资源至组提交或放弃；休眠和重连更新 Session 就绪代次，节点随之不再存活。

## 休眠和状态

共享路径汇总各组及业务需求；没有监测、选中、探测或保留调用者/连接时释放物理会话，按需重建。监测只让可用路径保持唤醒：故障路径在两次恢复尝试之间休眠。休眠保留测量和降级记录；停止 dae 测速不等于关闭仍在使用的协议会话心跳。

仍有可接收会话但缺少池容量时，即使路径健康检查失败，也可补建缺失会话；成功补建后及时重新验证，不能用建连成功代替健康验证。补建使可用容量增加时继续补齐，失败或没有可见容量进展时退避；建连返回成功但新会话立即丢失也不能清除退避。选中或保留调用者的路径可在暂停周期测速时修复容量。

`status` 的 Last/Avg10/EMA 是成功延迟。故障期间显示 `[degraded]`，首次恢复成功后显示 `[recover 5s/30s verified]`。分子是成功探测已验证的恢复时长，不是实时计时：首次成功为 `0s`，只有后续成功探测才推进，等待或探测超时时可以停在 `0s`；`30s` 是解除降级所需的观察窗口，不是故障确认超时。

`STATE` 同时显示健康状态和 worker 当前动作，包括 `healthy (verifying connectivity)`、`healthy (recheck in 5.0s)` 和 `confirming (queued for check slot)`。恢复观察期间的 recheck 倒计时来自实际调度时间；探测失败后显示 `fail`。故障路径显示 `unavailable` 和重试时间，例如 `unavailable (retry #3 in 72.0s)`，传输休眠时也是如此。只有物理会话已释放且最近一次观测没有失败时，才显示一次 `dormant`，历史延迟附带样本年龄。

API `selection.tracking` 只表示本组角色：`selected`、`monitoring` 或 `standby`。`standby` 不代表物理休眠或停止恢复：其他组可以共享监测结果，尚无监测的高优先级候选仍由升级调度发现。`recovery` 提供共享 worker 的动作及重试时间，节点的 `dormant` 单独表示物理休眠。`selection` 还提供 `recovery_elapsed`、`failure_recovery`、有效优先级、评分和 `measured_at`。

Prometheus 的 `dae_check_latency_seconds` 提供实测 `last`、`moving`；`dae_selection_score_seconds` 单独提供含偏移的选择评分，允许负数。
