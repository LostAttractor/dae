# API 鉴权与访问控制

## 职责与信任边界

API 向本地客户端和浏览器提供管理操作，同时向经过身份验证的 LAN 设备提供本机自助功能。管理权限与设备身份是两个独立维度：管理员可以管理整体配置，设备自助操作只能作用于当前连接识别出的设备。

| 组件 | 职责 |
| --- | --- |
| `internal/apiserver` | 监听入口、HTTP 请求约束、管理鉴权、浏览器会话和端点权限检查 |
| `control` | 将连接端点与当前数据路径的入口证据关联，提供设备身份及管理操作 |
| eBPF LAN hook | 观察 API 连接的入口、链路类型和源 MAC，维护该配置代的连接证据 |
| `web` | 展示服务端确认的访问模式和操作结果；服务端独立执行每个请求的授权 |
| `api` / `api/client` | 公开数据契约及 TCP/Unix 调用接口 |

API 流量按精确监听端点在内核直通，LAN hook 只记录身份所需证据，不为鉴权扩大透明代理或 MITM 的捕获范围。

## 管理权限

管理鉴权按连接类型和当前配置作一次决策，并向需要展示权限的响应提供相同的访问模式。

| 入口 | 授权依据 | 访问模式 |
| --- | --- | --- |
| Unix socket | 实际 Unix 监听连接及 socket 文件系统权限 | `unix` |
| 未配置 `api_key` 的 TCP | 当前请求通过 LAN 入口身份校验 | `lan` |
| 配置 `api_key` 的 TCP | 正确的 Bearer key，或没有显式 Authorization 时的有效浏览器会话 | `api_key` |

Unix 权限由实际连接上下文确定，请求头不能赋予 TCP 连接本地管理权限。密钥模式下显式 Authorization 优先于 Cookie，错误密钥不能被已有会话掩盖。无密钥模式逐请求验证 LAN 证据，Cookie 不提供可携带到其他连接的权限。

密钥或会话无效返回 `401`，LAN 身份无法确认返回 `403`。授权失败终止端点处理，不读取受保护状态或执行管理操作。

## LAN 与设备身份

控制面使用当前 TCP 源、目的 IP 和端口查找 eBPF 入口记录。记录必须在 30 秒内，且对应 LAN hook 仍然挂载。HTTP keep-alive 的后续数据同样刷新入口证据；新数据路径代使用自己的记录表。

以太网入口还要求回程直连路由和 ARP/NDP 邻居与所观察的源 MAC 一致；IPv6 zone、VLAN、网桥和 bond 按实际入口关系校验。纯 IP LAN 接口没有以太网设备身份，可以提供无密钥管理权限，但不能提供依赖 MAC 的设备自助操作。

`lan_interface` 定义受信任的入口范围。纯 IP 隧道入口的授权范围包含从该接口进入的来源及其后方路由子网；接口声明本身不提供加密或用户认证。私网地址、转发头和旧 Cookie 均不能代替当前入口证据。

设备自助端点始终解析当前连接的 LAN 身份，并要求有效的以太网单播 MAC。管理 key 不允许调用者任意指定自己的设备身份。配置说明及端点权限见[页面/API](../configuration/api.md)。

## 浏览器请求与会话

TCP API 要求 Host 为实际监听端点的字面 IP 和端口，并检查 Origin 与 `Sec-Fetch-Site`，防止跨源请求和域名重绑定。没有 Origin 的非浏览器客户端可以调用 API；POST、PUT、DELETE 还必须携带 `X-Dae-API: 1`。这些入口约束与端点鉴权同时生效。

密钥登录使用 Bearer key 签发有效期为 7 天的会话。Cookie 只保存到期时间、随机值和签名，不包含 key 原文；签名使用配置 key，并绑定请求 Host 和端口。Cookie 使用 `/api` 路径、`HttpOnly` 和 `SameSite=Strict`，TLS 连接上设置 `Secure`。

会话有效性由签名、绑定端点和到期时间共同决定。相同 key 的重载保留会话，key 轮换使已有会话失效。已有 Cookie 或 Unix 管理权限不能代替 key 签发新会话；退出清除当前浏览器的 Cookie。无密钥登录只校验入口并清除旧 Cookie，不创建浏览器会话。

管理 TCP 端口同时支持 HTTP 和 HTTPS。HTTPS 使用 daemon 管理的本地 CA 为连接的路由器 IP 签发证书，不依赖 MITM 宿主或设备 MAC，两种协议共用路由和权限校验。HTTP 传输会暴露密钥和可复用会话，安装并信任 CA 后应使用 HTTPS。仅证书挑战的 HTTPS GET 额外允许同一 IP、同一端口的发起 HTTP 安装页读取；元数据与其他 API 仍要求同源。CA 身份变化使旧 TLS 连接失效，避免旧 CA 握手认证新 CA 元数据；相同 CA 的重载保留 API 叶证书、挑战及 TLS 连接。

## 页面访问状态

页面以受保护 Selectors 响应中的 `auth_mode` 作为管理访问状态来源。登录响应成功后仍需完成该查询，才能显示管理员或 LAN 访问状态并启用管理控件。

`401` 和 `403` 清除相应的管理访问状态。其他请求错误显示操作失败，不推导新的授权状态。并发刷新按请求代次应用结果，较早请求的拒绝不能覆盖较新请求已经确认的权限。设备自助状态独立加载和校验，页面的管理状态不替代设备身份。

## 证书生命周期与验证边界

`component/ca` 提供加载、原子初始化、公开导出和叶证书签发能力。daemon 持有不可变 CA 身份，API 与 MITM 分别借用；`mitm` 不读取路径、不创建 CA。顶层 `certificate` 显式指定的路径只加载，不存在时不回退。默认托管目录不存在且 API 或 MITM 启用时才初始化自签名根 CA，已有损坏或不完整目录不自动更换身份。

重载先准备候选证书与服务，发布成功后才切换 daemon 身份；失败保留活动配置。相同指纹复用原身份与叶证书缓存，更换指纹时 API 和 MITM 同步切换。协议识别仅属于 `internal/apiserver` 的通用监听层。API 服务持有自己的叶证书和握手代次，信任测试使用该证据；不增加监听端口或改变 HTTP/TLS 分流。关闭监听器、禁用 HTTPS 或更换 TLS 身份时，先等待旧身份的签发与落盘完成，再允许替代身份使用存储目录；已取得旧 TLS 配置但尚未签发的握手被拒绝。仅排空请求不退役 TLS 身份。

普通元数据读取可能复用已放行的 TLS 连接，不能作为 CA 信任证据。API 的管理叶证书按 CA 指纹和路由器 IP 持久化，有效期内访问、重启和重载均复用。`POST /api/certificate/tests` 另行签发临时叶证书和新密钥，创建绑定源 IP、路由器 IP、页面 Origin 与签发代次的短期挑战，证书只由挑战持有，不写入磁盘或共享 MITM 缓存。

TLS 握手发生在 HTTP 路径可用之前。监听器根据真实 TCP 源 IP 和本地 IP，在未过期挑战中选择该地址对最新的证书；无挑战时使用管理证书。共享源 IP 的客户端无法按标签页隔离，其他源 IP 的管理连接不切换证书。HTTPS GET 只有在连接使用本次或更新挑战的证书时才返回证明，随后消费该挑战；管理证书与更早挑战的连接返回 `409` 并关闭，前端有界重试。管理证书的握手代次始终为零，后续加载或到期更新也不能充当挑战证明。并发挑战互不作废，完成顺序不受限。TLS session ticket 禁用，旧握手不能通过会话恢复充当新证明。

挑战每个源 IP 最多保留 8 个、全局最多 64 个，超额创建返回 `429`；一分钟过期，不依赖 MAC 或 MITM 代次。挑战期限与 X.509 有效期独立，临时证书向后额外预留五分钟客户端时钟偏差，不超过 CA 到期时间。过期清理在握手和挑战请求中执行，过期证书不再参与选择。证明成功移除对应挑战；该地址对没有剩余挑战后，新握手恢复原管理证书。daemon 重启丢弃临时挑战并加载管理证书。先前对管理证书接受的浏览器例外不能放行临时挑战证书；挑战有效期内依赖例外的新 HTTPS 连接可能失败，HTTP 安装页仍可访问。API 测试不会改变持久化管理证书、CA 或共享 MITM 签发缓存。

透明 MITM 验证由 `component/mitm/verify` 单独持有短期挑战，绑定设备、Origin、虚拟目标与当前运行代次；每个已验证 MAC 最多保留 8 条挑战及观测，全局最多 256 条，一分钟后过期，超额创建返回 `503`。浏览器收到匹配 proof 且同源查询确认捕获后才通过。CA 变化清除两类结果，设备或 MITM 代次变化只清除拦截结果。
