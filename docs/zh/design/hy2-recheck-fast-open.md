# HY2 recheck 与 FastOpen 失败处理

HY2 的连接错误通过现有连通性检查循环确认。`tcp4`、`tcp6`、`udp4`、`udp6` 分别记录健康、凭据和恢复窗口；共享 QUIC Session 的可用性与认证状态控制所有依赖模式。

## 业务错误与确认检查

某种模式处于 healthy 时，首个合格的上游错误请求检查并进入 confirming。该模式的后续错误合并到当前确认，不重启检查，也不增加失败代次。已不可用模式的业务错误不重置恢复退避。

确认期间，已选中的路径可以继续服务；新选择需要有效健康凭据。检查成功恢复对应模式，失败撤销该模式的可用性。旧检查结果不能清除后来发生的失败。已确认支持的模式保留其协议能力，普通超时不会将其标记为永久不支持。

| 错误 | 行为 |
| --- | --- |
| 上游读写错误、上游操作超时、FastOpen 应答超时或协议错误 | 请求对应模式的确认检查 |
| 调用方取消或 deadline、本地清理、目标拒绝、已知容量限制 | 处理当前操作，不请求确认 |
| 正常 EOF | 正常半关闭 |
| owner 已确认 QUIC 连接失效 | 进入 Session 故障与恢复流程 |
| 检查确认代理认证失败 | 阻断路径重试，等待环境变化或显式重查 |

同一路径使用一个检查调度器，网络操作共用进程级并发预算。常规检查覆盖已支持模式，每种模式失败时最多重试一次。显式单模式检查只验证所请求的模式。两次检查的错误均保留，第二次出现的认证失败不能被第一次超时掩盖。

## FastOpen 应答期限

首次 `Read` 开始解析代理应答时，设置最多 8 秒的内部 read deadline。有效 deadline 始终取内部期限与调用方期限中较早者；调用方延长或清除期限不能延长内部预算。应答成功后恢复最新的调用方 read deadline。

更短的调用方 deadline 中断解析时，关闭当前连接，不恢复读到一半的协议头。该错误保留调用方来源，不触发模式确认。内部预算耗尽属于协议侧错误，会请求确认。

8 秒从实际读取应答开始计算。正常 TCP relay 在连接返回后启动上游读取；从不调用 `Read` 的独立消费者依赖 `Close` 或 QUIC 存活机制结束连接。请求头发送受 DialContext/Handshake 的预算约束。

## 逻辑连接与共享会话生命周期

FastOpen 终结失败保存原始错误，Abort 当前 stream 的 Lease，并取消该 stream 的 I/O。relay 收到 Abort 后关闭连接并向 TCP 客户端发送 RST。后续读写返回保存的错误，`Close` 幂等释放资源。目标拒绝同样终止当前连接，但不触发模式确认；成功后的正常 EOF 继续半关闭。

不可恢复的 HY2 单流错误先执行带来源和资源信息的 stream Abort，再进入通用错误包装。单流失败不关闭共享 QUIC 或兄弟 stream，也不重放业务数据。共享 QUIC 失效由资源 owner 执行 Abort、cleanup 和 Connect。

健康检查不会主动销毁仍显示 connected 的共享 Session。无排队时，FastOpen 内部应答等待最多 8 秒，随后两次确认探测各受现有 8 秒预算约束；排队与共享会话恢复另受各自生命周期控制，不能据此承诺固定的整体恢复时限。
