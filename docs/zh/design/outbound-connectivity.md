# 出站连通性与故障转移

## 目标与故障模型

dae 的故障转移用于探测 dae 与代理节点之间连接的故障，并为后续请求选择可用路径。设计前提是节点通常不会只发生单一网络栈的故障，因此同一路径使用统一的代表探针判断健康状态。

经代理访问配置的 DNS 检测端点，可以验证路径是否具备代表性的连通能力。持续独立维护每个节点各协议、地址族的可用性需要反复尝试大量额外连接，dae 明确不采用这种设计。代表探针确认失败时先判定整个路径不可用，再触发能力重新发现；只影响其他模式或特定业务目标的异常可能无法由健康检查识别。这是探测成本与故障覆盖范围之间的设计取舍。

## 组件职责与共享边界

| 组件 | 拥有的状态与职责 |
| --- | --- |
| 共享路径 `pathRuntime` | 网络能力、统一健康状态、成功测量、健康凭据、故障代次和恢复观察；持有唯一的连通性 worker |
| 组内成员 `Dialer` / `groupBinding` | 组内统计身份、成功延迟统计、恢复窗口配置和完成状态；共享路径的实际探测结果 |
| 自动选择控制器 | 按目标网络过滤能力、比较降级状态与评分，安排候选发现和切换，提交前验证健康凭据 |
| 传输 `Runtime` / Session owner | 协议资源、连接容量、依赖租约，以及共享会话的关闭和重建 |

完整代理链、节点连接设置、入口与传输参数、探测配置相同的候选可以共享物理路径。组的优先级、延迟偏移、选择策略和恢复时长分别计算；共享健康状态不等于各组作出相同选择。

## 网络能力与健康状态

网络能力回答路径是否支持 `tcp4`、`tcp6`、`udp4`、`udp6`。能力记录属于一轮发现周期：实际探测成功才能确认支持，协议明确拒绝才标为不支持，普通超时保留为未知。周期内已确认的能力保留；路径检查确认故障后，全部模式重新进入未知状态，包括此前标为不支持的模式。其他模式探测成功不能推导出未知能力。

健康状态回答该路径当前是否可用。代表模式按 `tcp6 → tcp4 → udp6 → udp4` 顺序选择本轮第一个已支持模式。日常检查、业务故障确认、恢复观察和切换前验证均使用这个代表探针。重新发现可以产生新的代表模式，恢复后的日常检查仍只使用一个探针。

| 状态 | 含义与选择行为 |
| --- | --- |
| 未知 | 尚无有效连通性结果，需要发现能力和验证路径 |
| 健康 | 所有已支持模式共享可用状态；传输也必须处于可接收状态 |
| 确认中 | 业务错误触发代表探针；已选路径可以继续服务，新选择需要新的有效健康凭据 |
| 不可用 | 所有模式停止接收新选择，等待恢复验证或能力重新发现 |

路径健康时，首个合格的上游错误进入确认状态。后续业务错误合并到同一轮确认，不增加失败代次或重启检查。代表探针成功恢复共享健康状态，失败确认路径故障。旧检查结果不能清除在其开始后报告的故障。

## 故障后的能力重新发现

代表检查确认失败时，先在同一次状态更新中使路径不可用、进入故障降级、使旧凭据失效，并将全部模式置为未知，再通知各组选择器。选择器立即开始选择替代路径，不等待故障节点完成多模式探测；额外探测不增加故障确认的尝试次数，也不延长请求的选择预算。

共享 worker 随后安排一轮后台能力发现。每个未知模式实际尝试一次，成功模式参与新的代表选择，失败模式暂不承接流量。例如 TCP6 失败、TCP4 成功时，可以用 TCP4 恢复路径，TCP6 保持未知。此前明确不支持的模式也会在新一轮中重新尝试。新代表成功只恢复本轮已确认模式的可用性，并按原有 `failure_recovery` 窗口观察，不直接解除降级。

这一轮发现可以在选择器切走、停止监测后完成。后续未知模式的自动发现按退避调度，并服从监测和恢复需求；显式验证也可以按需发现目标模式。没有后续需求或本轮全部模式明确不支持时停止，避免为故障节点建立永久的逐模式监测。建连失败继续遵守连接重试退避；认证、证书等阻断错误等待环境变化或显式重查，不通过更换模式绕过阻断。

## 探测调度与健康凭据

同一路径的 worker 串行调度能力发现、健康验证和容量补充，网络操作共用进程级并发预算。常规健康检查失败时最多重试一次，两次尝试的错误均参与故障分类，认证或证书错误阻断自动重试，等待环境变化或显式重查。

同一路径保存一份健康凭据，绑定路径、故障代次和 Session 就绪代次，供所有已支持模式使用。新故障或会话代次变化使旧凭据失效。传输建连成功本身不能代替连通性验证。

不同已支持模式的并发验证合并为一次代表探测。未知能力先实际发现，再取得或复用本轮有效的代表探针凭据。成功凭据在选择交接完成前持有传输资源，防止候选在验证与提交之间休眠。

`probe_timeout` 包含排队、建连和验证；`selection_timeout` 限制整轮选择。共享检查使用较早调用者的预算结束时，较长预算的调用者可以在自己的剩余时间内重试，重试不重置其截止时间。

## 故障降级与恢复

确认故障后，路径在各组中降级。首次恢复成功允许降级兜底，并启动恢复观察。观察期间按 `min(check_interval, 5s)` 验证；各组在自己的 `failure_recovery` 窗口末次验证成功后解除降级。仅时间到期不能证明恢复，失败或停止观察会重启尚未完成的窗口。

恢复观察属于共享路径，各组共用实际探测并分别判断窗口是否完成。日常测量和恢复窗口末次成功均可直接作为切换凭据，不为其他已支持模式追加连接。延迟统计只接收成功的代表探针样本，失败不写入延迟窗口。

自动选择先过滤能力和可用性，再按正常优先于降级、优先级和策略评分选择。当前路径仍可用时后台验证候选；启动或失效时，请求在总选择预算内等待已验证的替代路径。具体策略与配置见[自动节点选择](../configuration/outbound-selection.md)。

## 传输与数据路径边界

业务连接错误提供确认探测的线索，传输 owner 提供共享资源失效的事实。调用方取消、目标拒绝、本地清理和已知容量限制不直接判定路径故障；单流错误也不授权关闭共享 Session。共享资源的 Abort 沿实际依赖关系终止连接，容量补充保留健康的兄弟连接。

健康检查不会主动销毁仍然 connected 的 Session。失败业务连接结束后不重放数据，后台恢复供后续请求使用。没有监测、选中、探测或保留调用者/连接需求时，物理会话可以休眠，逻辑候选及历史测量保留。协议期限和 relay 终止语义见[Relay 生命周期与恢复](../development/relay-error-recovery.md)。

内核路由沿用已有捕获边界。节点监测和故障切换不扩大用户态流量接管范围；未命中代理、DNS 或显式高级功能规则的 direct 流量继续在 eBPF 中直通。

## 观测数据

路径健康、成功测量、故障记录和 worker 调度状态是状态展示的共同来源。各组基于共享测量计算自己的统计和评分；`status`、API 和 Prometheus 复用这些状态及现有底层计数，不为展示重新探测或重复计数。恢复进度表示成功探测已验证的时长，不是实时流逝时间。
