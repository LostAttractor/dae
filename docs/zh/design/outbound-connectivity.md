# 出站连通性与故障转移

## 目标与故障模型

dae 的故障转移用于探测 dae 与代理节点之间连接的故障，并为后续请求选择可用路径。设计前提是节点通常不会只发生单一网络栈的故障，因此同一路径使用统一的代表探针判断健康状态。

经代理访问配置的 DNS 检测端点，可以验证路径是否具备代表性的连通能力。持续独立维护每个节点各协议、地址族的可用性需要反复尝试大量额外连接，dae 明确不采用这种设计。代表探针确认失败时先判定整个路径不可用，恢复尝试再逐个验证已支持模式；只影响其他模式或特定业务目标的异常可能无法由健康检查识别。这是探测成本与故障覆盖范围之间的设计取舍。

## 组件职责与共享边界

| 组件 | 拥有的状态与职责 |
| --- | --- |
| 共享路径 `pathRuntime` | 网络能力、模式可达性、统一健康状态、存活状态、成功测量、故障代次、恢复调度和恢复观察；持有唯一的连通性 worker |
| 组内成员 `Dialer` / `groupBinding` | 组内统计身份、成功延迟统计、恢复窗口配置和完成状态；共享路径的实际探测结果 |
| 自动选择控制器 | 按目标网络过滤能力、比较降级状态与评分，由存活节点接替并请求切换后验证；没有存活节点时安排选举 |
| 传输 `Runtime` / Session owner | 协议资源、连接容量、依赖租约，以及共享会话的关闭和重建 |

完整代理链、节点连接设置、入口与传输参数、探测配置相同的候选可以共享物理路径。组的优先级、延迟偏移、选择策略和恢复时长分别计算；共享健康状态不等于各组作出相同选择。

HTTP/2 与 QUIC 连接池使用 `netproxy.PoolState` 聚合成员可用性、容量需求和故障事件，协议实现继续负责握手、流准入、GOAWAY 及实际连接关闭。池状态不启动重试定时器，也不推导节点健康。成功替换资源后，旧资源的迟到错误不能覆盖当前恢复状态。

`Runtime` 和休眠传输共用连接所有权包装，保留原生 socket、半关闭和依赖租约能力；嵌套包装合并释放回调，每个所有者只释放一次。物理代际仍独立排空，休眠需求由上层监测、组选择和保留调用者决定。

## 网络能力与健康状态

网络能力回答路径能否承载 `tcp4`、`tcp6`、`udp4`、`udp6`。实际探测成功才能确认支持，协议明确拒绝才标为不支持，普通超时保留为未知；其他模式探测成功不能推导出未知能力。能力是学到的节点事实，故障不改变它：不再应答的已支持模式只是不可达，不会变成未知或不支持。节点的能力变化由 reload 处理：reload 与节点地址、MPTCP 记忆一起重学全部路径的能力，且不中断服务。不支持的模式回到未知，由能力探测、选举和显式检查重新发现；已支持的模式继续承接流量并标记待重学，直到探测成功或协议明确拒绝，代表模式由自身的健康检查确定，其余模式随能力探测确定。

探针仅解析和访问本次检测的地址族，不进行跨族连接竞速。`udp_check_dns` 使用域名时，每次检查复用内部解析器的 TTL 缓存，过期后重新解析；显式配置的 IP 保持固定。某一地址族的 DNS 查询延迟不阻塞另一族的探测。

模式可达性回答已支持的模式此刻能否应答：最近一次探测失败的已支持模式标记为失效（failing），不承接流量，也不能代表路径，直到该模式再次探测成功。可达性只随探测结果变化，能力只随能力探测变化，两者互不推导。

健康状态回答该路径当前是否可用。代表模式按 `tcp6 → tcp4 → udp6 → udp4` 顺序选择第一个已支持且未失效的模式。日常检查、业务故障确认、恢复观察、选举测试和切换后验证均使用这个代表探针；日常检查同时重测失效模式，没有失效模式时只有一个探针。

| 状态 | 含义与选择行为 |
| --- | --- |
| 未知 | 尚无有效连通性结果，需要发现能力和验证路径 |
| 健康 | 所有已支持模式共享可用状态；传输也处于可接收状态且就绪代次匹配时，路径存活 |
| 确认中 | 业务错误触发代表探针；已选路径可以继续服务，但路径不存活，不能被新选择 |
| 不可用 | 所有模式停止接收新选择，按路径自身的恢复调度等待恢复尝试 |

路径健康时，首个合格的上游错误进入确认状态。后续业务错误合并到同一轮确认，不增加失败代次或重启检查。代表探针成功恢复共享健康状态，失败确认路径故障。旧检查结果不能清除在其开始后报告的故障。

## 故障后的恢复

代表检查确认失败时，先在同一次状态更新中把代表模式标为失效、使路径不可用并进入故障降级，再通知各组选择器。能力保持不变。选择器立即选择替代路径，不等待故障节点的恢复尝试；恢复尝试不增加故障确认的尝试次数，也不延长请求的选择预算。

恢复由共享路径自己负责，只有一个截止时间。每次尝试等待目前停机时长的四分之一，至少 1 s、至多 `check_interval_max`，带抖动：恢复会在停机时长约 25% 的时间内被发现，长期失效的路径只需对数级的尝试次数。Session 变化，包括路径自身重连产生的事件，不会提前下一次尝试；建连失败同样计为一次失败的尝试。恢复尝试并发探测全部已支持模式，第一个按代表顺序应答的模式成为新代表。例如 TCP6 失败、TCP4 成功时，用 TCP4 恢复路径，TCP6 保持失效，由后续日常检查重测。新代表成功后按原有 `failure_recovery` 窗口观察，不直接解除降级。从未确认任何模式的路径，以能力探测作为恢复尝试，遵循同一调度。

恢复需求来自组：自动策略的组始终监测自己的故障候选，选举和升级检查跳过这些候选，路径恢复后通知共享它的所有组；selector 组只监测选中或跟踪的成员。没有监测需求的故障路径不再尝试。监测只让可用路径保持唤醒，故障路径在两次尝试之间释放物理会话。认证、证书等阻断错误等待环境变化或显式重查，不通过更换模式绕过阻断。

## 探测调度与存活状态

同一路径的 worker 依次调度健康验证与恢复尝试、未知模式的能力发现和容量补充。三者的重试共用一条规则：等待状况已持续时长的四分之一，至少 1 s、至多 `check_interval_max`，状况结束会在其持续时长约 25% 的时间内被发现；无可用节点网络的选举轮次同样如此，上限为 `upgrade_interval_max`。选举和升级发起的单次测试中，建连和代表探测属于整条路径：路径存活之前（尚无已知能力时为 Session 可接收之前）逐个执行，优先代表测试；之后不同模式的测试并发、互不排队，同一模式依次执行。网络操作共用进程级并发预算。常规健康检查失败时最多重试一次，两次尝试的错误均参与故障分类，认证或证书错误阻断自动重试，等待环境变化或显式重查。

路径健康、Session 可接收且就绪代次与最近一次成功检查一致时，所有已支持且未失效的模式存活。存活就是路径有效的证明，组可以直接用它接替，不再探测。新故障使路径进入确认或不可用；休眠和重连推进就绪代次，使路径不再存活，直到新的检查成功。传输建连成功本身不能代替连通性验证。

选举测试只在路径不存活时探测；不同已支持模式的并发测试合并为一次代表探测，排队中的测试由请求之后成功的代表探测满足。未知能力需要实际发现；路径不存活时，先由代表探测证明路径再发现，发现缓慢或失败只影响请求该能力的测试。成功测试在组提交或放弃之前持有传输资源，防止候选在测试与提交之间休眠。

组因当前路径失效而接替其他路径，或切换到未受监测的路径时，请求一次切换后验证；首次选择和触发本次决策的路径不验证。验证需要一个晚于切换依据的代表结果：进行中的代表探测在该依据之后结束，可以直接满足验证；路径空闲时立即启动一次代表探测，暂停周期测速时也会执行。同一路径的重复请求合并，只有能力发现、容量补充等不产生代表结果的操作结束后才补测。验证失败即普通健康失败，组随即切换。

`probe_timeout` 包含排队、建连和验证；`selection_timeout` 限制每轮选举或升级测试，以及没有存活节点时请求的等待，请求自身的截止时间同样有效。共享检查使用较早调用者的预算结束时，较长预算的调用者可以在自己的剩余时间内重试，重试不重置其截止时间。

## 故障降级与恢复

确认故障后，路径在各组中降级。首次恢复成功允许降级兜底，并启动恢复观察。观察期间按 `min(check_interval, 5s)` 验证；各组在自己的 `failure_recovery` 窗口末次验证成功后解除降级。仅时间到期不能证明恢复，失败或停止观察会重启尚未完成的窗口。

恢复观察属于共享路径，各组共用实际探测并分别判断窗口是否完成。日常测量和恢复窗口末次成功都使路径保持存活，可直接用于切换；除重测失效模式外，不为其他已支持模式追加连接。延迟统计只接收成功的代表探针样本，失败不写入延迟窗口。

自动选择先过滤能力和可用性，再按正常优先于降级、优先级和策略评分选择。存活节点立即接替失效或被超越的当前路径。没有可用路径的选举进行中，出现的存活节点同样立即接替；选举继续，只有找到不计容差也更优的候选才再次提交。接替使服务层级下降时，立即测试更高层级中未受监测的候选，受监测的候选恢复后会自行存活。当前路径仍可用时，休眠的更优候选在后台测试；没有存活节点时，请求在选择预算和自身截止时间内等待选举结果，失败后降级。具体策略与配置见[自动节点选择](../configuration/outbound-selection.md)。

## 传输与数据路径边界

业务连接错误提供确认探测的线索，传输 owner 提供共享资源失效的事实。调用方取消、目标拒绝、本地清理和已知容量限制不直接判定路径故障；单流错误也不授权关闭共享 Session。共享资源的 Abort 沿实际依赖关系终止连接，容量补充保留健康的兄弟连接。

健康检查不会主动销毁仍然 connected 的 Session。失败业务连接结束后不重放数据，后台恢复供后续请求使用。没有监测、选中、探测或保留调用者/连接需求时，物理会话可以休眠，逻辑候选及历史测量保留。协议期限和 relay 终止语义见[Relay 生命周期与恢复](../development/relay-error-recovery.md)。

内核路由沿用已有捕获边界。节点监测和故障切换不扩大用户态流量接管范围；未命中代理、DNS 或显式高级功能规则的 direct 流量继续在 eBPF 中直通。

## 无可用节点降级

组按网络类型发布可用性，内核连通性表、诊断和 DNS 出口判断读取同一份发布结果。选举期间保留已发布的可用状态，内核继续把流量交给等待选举的用户态；选举失败后发布不可用。用户态按拨号目标的地址族选择节点，名称目标可以使用任一地址族；组没有可用节点时降级，请求自身已结束时直接失败，显式 HTTP 策略不降级。

不可用状态分为两种：内核直接降级，或交给用户态决定。默认 `reroute_mode: while_possible` 时，不可用组的流量始终交给用户态，以便可信的嗅探名称把它重路由到可用出口，仍不可用时按 `no_connectivity_behavior` 降级；代价是组不可用期间这部分流量的用户态处理。`while_needed` 或 `none` 时，自动选择的组尚未选出节点且此前没有选举失败时（启动期，包括 `check_async` 的组），发布为选举中：内核把流量交给用户态，用户态等待选举结果，失败后再降级。其他情况下普通代理流量由内核直接降级：`block` 丢弃，`direct` 在内核直连转发，不进入用户态；分片首片与完整报文规则相同。DNS 与捕获流量始终由用户态按同一状态降级。带 `skip_while_noalive` 的规则只在目标可用时匹配，按流量的地址族判断，选举中同样跳过，不触发降级。

开启 `dial_target_override` 时，代理把嗅探到的 TCP 名称经任一地址族拨出。因此即使不是 `while_possible`，组在一个 TCP 地址族不可用、另一族可用时，该族的流量仍交给用户态：嗅探到可信名称的流量经另一地址族的节点代理，没有名称的流量在用户态按 `no_connectivity_behavior` 降级。另一族的可用性变化时，该族的发布状态随之更新。UDP 中继保留客户端地址，不受影响。

降级连接属于原组对应网络类型的 fallback 代次。组的 `reselect_behavior` 或全局 `route_change_behavior` 为 `close` 时，代次可以结束：`route_change_behavior: close` 下恢复、`reselect_behavior: close` 下改选，以及任一策略下删除组，都会关闭旧代次的用户态 relay。内核直连的 fallback 流在 TCP 流状态和 UDP 路由缓存中记录代次令牌，代次结束时令牌从共享集合撤销，后续报文按失效处理，具体行为见[Relay 生命周期与恢复](../development/relay-error-recovery.md)。已发布的代次结束、替代代次尚未发布时（例如 reload 交接期间），新流交给用户态降级，不加入已结束的代次。策略均为 `keep` 时不分配令牌，内核 fallback 流持续到自然结束；reload 改为 `keep` 时，此前带令牌的连接不再随恢复或改选结束，但仍随删除组结束。令牌集合只属于当前 Runtime，发行序号由固定内核表跨进程保留且不回卷，重启不能重用旧令牌；集合已满、序号耗尽或发行失败时记录警告，不能把需要约束的新流降为无令牌直通。TCP 直通连接属性表按 LRU 淘汰；条目被淘汰的连接按原生转发继续，不再受代次约束，也不会因此中断。

状态先发布、旧代次后结束：恢复时内核先按原组路由新流；改选或 reload 交接时先发布新代次，新流不会加入即将结束的代次。

正常退出会完整清理 dae 自有挂载、固定表和内部网络资源，不继续执行离线规则，也不提供单独的 unload 命令。无法完成清理的异常退出才保留内核兜底：已有有效直连保持 mark 和代次约束，已有代理 TCP 随进程的 socket 结束，必须重新握手。

异常退出的新出站流由独立的 `unexpected_exit_behavior` 控制。默认 `bypass` 绕过全部旧路由、block、DNS/MITM 捕获和目的地址重写规则，新 TCP 握手与新 UDP 源生命周期保留报文原有 mark、使用令牌 0；旁路接纳的连接重启后仍可保持直连，不会自动接回代理；希望避免这种泄露风险时选 `block`。block 保留已有原生转发及入站回复，不扩展成入站防火墙。旧 UDP proxy binding/cache 不能仅通过改发 DNS 目的端口逃逸。无足够生命周期证明的离线分片保守丢弃。两种模式均依赖残留 hook，不约束未接管的接口，也不能在 hook 已被卸下后继续约束流量。

启动中、在线、终态离线是不同状态，启动中不启用异常旁路，终态 Runtime 不能再次发布。启动仅为显式登记的当前 daemon 自身 socket 保留豁免，进程退出撤销登记；相同 mark 不构成身份。普通 fallback 令牌的发行序号最后清理：旧连接条目、挂载或其他清理步骤失败时保留序号，防止下次启动复用旧授权。

含 BPF timer 的两张 UDP 表使用每个 Runtime 私有的 pin。仅保留程序引用不足以维持 timer 所需的用户引用，因此这些 pin 在异常退出后仍保留；冷启动创建新表，不继承旧组编号或 UDP cache。启动、发布和退出只在核实已挂载程序不再引用后清理旧 timer pins，不引入按连接定时回收。

## 观测数据

路径健康、成功测量、故障记录和 worker 调度状态是状态展示的共同来源。各组基于共享测量计算自己的统计和评分；`status`、API 和 Prometheus 复用这些状态及现有底层计数，不为展示重新探测或重复计数。恢复进度表示成功探测已验证的时长，不是实时流逝时间。
